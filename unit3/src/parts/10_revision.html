Notation
  • Rectangle = entity · double rectangle = weak entity
  • Diamond = relationship · double diamond = identifying relationship
  • Ellipse = attribute · underlined = key · dashed underline = partial key
  • Double ellipse = multivalued · dashed ellipse = derived · ellipse with sub-ellipses = composite
  • Single line = partial · double line = total participation
  • 1 / N / M near an entity = how many of that entity per one of the other
  • Korth arrow diamond → entity = “one” side · Ramakrishnan arrow entity → diamond = “each at most once”
  • (min,max) next to E = how many instances each e takes part in
  • ISA triangle = specialization/generalization · box around relationship = aggregation
ER → tables
  • Strong entity → table, key → PK; composite → components; derived → not stored
  • Multivalued → new table (key, value), PK both
  • Weak → table, PK = owner PK + partial key, FK cascade
  • 1:N → FK in N side (NOT NULL if N side total)
  • 1:1 → FK UNIQUE in total side; both total → merge into one table
  • M:N → new table, PK = both keys + rel attributes
  • n-ary → new table, PK = keys of non-“1” sides
  • Recursive → role-named copy of the key
  • ISA → super + subs (always) / subs only (total) / one table + type (disjoint) / + flags (overlap)
  • Aggregation → use the aggregated relationship’s PK
TermOne-line definition
Entity / entity type / entity setan object / its schema / the collection of current entities of that type
Relationship type / setassociation among entity types / the current set of instances (subset of E1 × … × En)
Degreenumber of participating entity types (unary, binary, ternary)
Rolethe function an entity plays in a relationship; essential in recursive relationships
Cardinality ratiomaximum number of relationship instances an entity can participate in (1:1, 1:N, M:N)
Participationminimum: total (every entity participates) or partial
Structural constraintscardinality ratio + participation, or the (min,max) pair
Weak entityno key of its own; identified by owner key + partial key; total participation in identifying relationship
Specializationtop-down: define subclasses of an entity type
Generalizationbottom-up: combine entity types into a superclass
Disjoint / overlappingan entity in at most one subclass / possibly several
Total / partial specializationevery superclass entity in some subclass / not necessarily
Aggregationrelationship + its entities treated as an entity, to relate relationships
Attribute inheritancesubclass gets all attributes and relationships of its superclass
