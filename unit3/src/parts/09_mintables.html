9“Minimum number of tables” — method and class-notes questions

Papers say “convert into relational schema with the minimum number of tables”. This means: apply the merging rules of section 8 wherever they are allowed (1:N, 1:1, weak entities) and create separate tables only where they are unavoidable.

9.1 Counting rule

Minimum tables =

(number of strong entity types) + (number of weak entity types) + (number of M:N relationships) + (number of n-ary relationships, n ≥ 3) + (number of multivalued attributes) − (number of 1:1 relationships with total participation on both sides).

1:N, N:1, 1:1 (not total both) and identifying relationships add nothing. Recursive M:N adds one; recursive 1:N adds nothing. Specialization: + one table per subclass with option (a), or replace the superclass with the subclasses in option (b).

Traps
  • Participation never removes an M:N table (drill D5 below). Only 1:1 total-both reduces the count.
  • A chain of 1:N relationships still needs one table per entity (D4). Entities are never merged through 1:N.
  • A multivalued attribute always costs one extra table, even on a weak entity or a relationship.
  • Merging two entities through 1:1 total-both does not stop other relationships from referring to either key (D2).

9.3 Class-notes question 1 — A, B, C (= End-Sem 2023 Q3(c))

The diagram uses the Ramakrishnan arrow: A → R1 means each A takes part in R1 at most once (each A has at most one B); likewise A → R2 (each A has at most one C). R3 has no arrows: many-to-many.

{{erm:p23|Each A has ≤ 1 B (R1) and ≤ 1 C (R2); B–C is M:N.}}
  • AR1(a1, a2, b1) and AR2(a1, a2, c1) have the same primary key a1, so (class notes) “these can be combined” → A(a1, a2, b1, c1).
  • R3 is M:N → R3(b1, c1); {b1, c1} is its key. Class notes: “if R3 were 1:1, then b1 and c1 would each separately be a candidate key.”
  • Minimum tables = 4.

9.4 Class-notes question 2 — E1, E2, E3

9.5 Class-notes question 3 — M, P, N (“find the minimum number of tables”)

{{erm:q_mpn|M has total participation in R1 and R1 points to P (many-to-one). N is weak, identified by P through R2.}}
  • R1 is N:1 with M total → merged into M; p1 is a NOT NULL FK (class notes: “not null”).
  • N is weak → N(p1, n1, n2) with PK (p1, n1); the identifying relationship R2 needs no table.
  • Minimum tables = 3: P(p1, p2), MR1(m1, m2, m3, p1), NR2(p1, n1, n2).

9.6 Class-notes question 4 — A, B, C, D (“find answer”)

{{erm:q_abcd|R1: A total, arrow to B (each A has exactly one B). R4: D total, arrow to B. R2 and R3 have no arrows (M:N).}}

The class notes list the answer as AR1, B, R2, C, R3, DR4 — exactly what the rules give: 6 tables. R1 and R4 are merged into A and D with NOT NULL foreign keys b1; R2 and R3 need their own tables.
