8Database languages, interfaces and design phases

8.1 Database languages

A DBMS provides languages to define the schema and to read and update data. In SQL these are sub-languages of one language (details and syntax: Unit 2 §5).

LanguagePurposeCommands
DDL — Data Definition LanguageDefine/modify the database structure (schema), constraints, storage. Output goes into the data dictionary. Auto-committed.CREATE, ALTER, DROP, TRUNCATE, RENAME, COMMENT
DML — Data Manipulation LanguageAccess and change the data (instance): retrieve, insert, delete, modify. Can be rolled back.SELECT, INSERT, UPDATE, DELETE, MERGE
DCL — Data Control LanguageControl access rights (privileges).GRANT, REVOKE
TCL — Transaction Control LanguageManage the changes made by DML as transactions.COMMIT, ROLLBACK, SAVEPOINT
Example
CREATE TABLE student (roll CHAR(11) PRIMARY KEY, name VARCHAR(40), cgpa DECIMAL(4,2));  -- DDL
INSERT INTO student VALUES ('2023UIT001', 'Asha', 8.9);                               -- DML
GRANT SELECT ON student TO accounts_clerk;                                            -- DCL
COMMIT;                                                                               -- TCL

8.2 Procedural vs non-procedural DML

Procedural (low-level, navigational)Non-procedural / declarative (high-level)
User specifies what data is needed and how to get it (step by step).User specifies only what data is needed; the DBMS decides how.
Record-at-a-time; loops over recordsSet-at-a-time
Harder to write, needs knowledge of the structureEasier; optimiser chooses the plan
e.g. relational algebra (sequence of operations), CODASYL DML, PL/SQL, C/Java loopse.g. SQL SELECT, tuple/domain relational calculus, QBE

8.3 DBMS interfaces

  • Menu-based (web clients, browsing) — lists of options lead the user; no syntax to remember.
  • Form-based — fill in a form to insert or to query (bank account opening form).
  • Graphical (GUI) — schema shown as a diagram; query by pointing (MySQL Workbench).
  • Natural-language — request written in English is interpreted (chatbots, “text-to-SQL”).
  • Interfaces for parametric users — a small set of operations with function keys (bank tellers, ticket counters).
  • Interfaces for the DBA — privileged commands: create accounts, set parameters, grant authorisation, change schema.

8.4 Phases of database design

{{svg:design_phases}}
  1. Requirements collection and analysis — interview users; list data and operations.
  2. Conceptual design — high-level conceptual schema (ER diagram), independent of any DBMS.
  3. Logical design (data-model mapping) — convert ER to the DBMS’s model (relational tables), normalize.
  4. Physical design — choose storage structures, indexes, partitions for performance on the chosen DBMS (e.g. Oracle, DB2).
