14.2 Levels of abstraction and data independence

End-sem 2022 Q1(a)4 marks

What is data abstraction? Explain in brief with the help of a suitable diagram.

Show answer

Data abstraction is the process of hiding the complex, irrelevant details of how data is stored and maintained from users, showing each user only the data relevant to them. Since many database users are not computer-trained, the DBMS provides abstraction at three levels:

  1. Physical (internal) level — lowest level; describes how data is actually stored: record formats, file organisation, indexes, block placement.
    e.g. STUDENT records stored as 60-byte records in stu.dat with a B+ tree index on Roll.
  2. Logical (conceptual) level — describes what data is stored and the relationships among the data, for the whole database, in terms of simple structures (tables).
    e.g. STUDENT(Roll, Name, Dept, CGPA), COURSE(CID, Title), ENROLLED(Roll, CID, Grade).
  3. View (external) level — highest level; describes only part of the database for a particular user group; many views for one database.
    e.g. a student sees only their results; the accounts office sees only fee data.

Diagram: draw the three-schema figure of section 4 — View 1, View 2, … View n at the top, connected to the logical level, connected to the physical level, connected to the disk; label the external/conceptual and conceptual/internal mappings.

Benefits: simplicity for users, security (users see only their view), and data independence — physical changes do not affect the logical level, logical changes need not affect views.

Mid-sem 2023 Q1(a)2 marks

How is data abstraction ensured in DBMS?

Show answer

Through the three-schema architecture: the DBMS keeps a separate internal, conceptual and several external schemas in its catalog. Users and programs work only with an external schema (view) or the conceptual schema; the DBMS translates every request through the external/conceptual and conceptual/internal mappings into operations on stored files, and translates results back. Declarative SQL (what, not how), views and privileges on views hide storage details and irrelevant data. Hence users never see how or where data is physically stored.

Mid-sem 2023 Q1(b)1 mark

What is a data model? Explain the concept of data independence.

Show answer

A data model is a collection of conceptual tools for describing data, relationships, data semantics and consistency constraints (e.g. relational, ER, hierarchical, network). Data independence is the ability to change the schema at one level without changing the schema at the next higher level: physical (change storage/indexes without changing the conceptual schema) and logical (change the conceptual schema, e.g. add a column, without changing external views or programs).

Mid-sem 2024 Q2(a)2 marks

Describe the concept of data abstraction using an example of a database schema and how it helps in simplifying database management.

Show answer

Data abstraction hides storage details and shows each user only what they need, at three levels. Example — a library database:

  • Physical: BOOK records in a heap file with a B+ tree index on ISBN and a hash index on Author.
  • Logical: BOOK(ISBN, Title, Author, Copies), MEMBER(MemID, Name), ISSUE(ISBN, MemID, IssueDate, DueDate).
  • View: members see Available(Title, Author, Copies); the librarian sees Overdue(MemID, Name, Title, DueDate).

How it simplifies management: users and programmers work with simple tables/views and need not know files or indexes; the DBA can re-organise storage or add indexes without touching applications (physical data independence); views restrict access (security); each user group gets an interface suited to it.

Mid-sem 2025 Q1(b)2 marks

A hospital management system stores detailed patient records. Doctors want to see only medical history, while the billing department requires payment details, not medical history. Using levels of abstraction (physical, logical, view), explain how DBMS provides these different perspectives without duplicating data.

Show answer
  • Physical level: one set of stored files — PATIENT, TREATMENT and BILL records on disk with indexes on PatientID. Stored once.
  • Logical level: PATIENT(PatientID, Name, DOB, Phone), MEDICAL_HISTORY(PatientID, Date, Diagnosis, Prescription), BILL(BillID, PatientID, Amount, Mode, Status).
  • View level: DoctorView = Name + diagnosis/prescription history (join of PATIENT and MEDICAL_HISTORY); BillingView = Name + bill details only. Each department is granted access only to its view.

Views are virtual: they are definitions stored in the catalog and computed from the same base tables through the external/conceptual mapping, so the two perspectives exist without any duplication, and a change (new phone number) is seen in both.

Mid-sem (summer) Q2(a)1.5 marks

Consider a university database whose storage structure is modified from HDD-based storage to SSD-based storage. Explain whether application programs will require modification. Relate your answer to logical and physical data independence with examples.

Show answer

No. Moving from HDD to SSD changes only the internal (physical) schema — where and how blocks are stored. The DBMS updates the conceptual/internal mapping; the conceptual schema (STUDENT, COURSE … tables) is unchanged, so views and application programs need no change. This is physical data independence (other examples: adding an index, changing file organisation).

By contrast, logical data independence is needed when the conceptual schema changes — e.g. adding an Email column to STUDENT or splitting STUDENT into STUDENT and ADDRESS; programs keep working if views are redefined over the new tables. Logical independence is harder to achieve than physical.

Mid-sem (summer) Q2(b)1.5 marks

A banking database is accessed by customers, clerks, managers and auditors. Explain how the three-schema architecture (External, Conceptual, Internal) supports data abstraction and security for these users.

Show answer
  • Internal schema: account and transaction files, indexes on AccountNo, encryption at rest — hidden from all four user groups.
  • Conceptual schema: CUSTOMER, ACCOUNT, TRANSACTION, LOAN, BRANCH, EMPLOYEE with keys and constraints — managed by the DBA.
  • External schemas: customer — own accounts, balance and statement only; clerk — customer details and deposit/withdrawal entry for their branch, no salaries; manager — branch-wide accounts, loans and reports; auditor — read-only view of all transactions and logs.

Abstraction: each user sees a simple view and none sees files. Security: privileges are granted on the views (GRANT SELECT to auditor, no UPDATE), so data outside a user’s view is invisible and unchangeable to them.

Mid-sem 2021 Q1(c)4 marks

How are data independence and data abstraction achieved in DBMS?

Show answer

Data abstraction is achieved by the three-schema architecture: internal schema (how data is stored), conceptual schema (what data and relationships), external schemas (user views). Users interact only with views/conceptual schema; the DBMS uses mappings to convert requests down to the stored data and results back. [Draw the three-schema diagram.]

Data independence is achieved because of these mappings: when one level changes, only the mapping to the level above is changed.

  • Physical data independence — internal schema changes (new index, new file organisation, new disk) are absorbed in the conceptual/internal mapping; the conceptual schema and programs do not change.
  • Logical data independence — conceptual schema changes (new attribute, new table, splitting a table) are absorbed in the external/conceptual mapping by redefining views; external schemas and programs do not change. It is harder, because programs depend on the logical structure.

Abstraction = separate schemas at three levels; independence = changes absorbed in the mappings between them.
