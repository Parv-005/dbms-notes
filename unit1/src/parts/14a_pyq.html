14.1 File system vs DBMS

End-sem 2025 Q1(a)5 marks

During the Special Intensive Revision (SIR) of electoral rolls, the Election Commission needs to update, verify and correct lakhs of voter records across districts. Currently the data is stored in multiple Excel/CSV files maintained separately by different officers. Analyze the risks of continuing with a file-based system for SIR and justify how adopting a DBMS can improve accuracy, security, deduplication and faster roll revision. Provide five strong arguments.

Show answer

Current situation. Each district / booth officer keeps a separate Excel or CSV file of voters. This is a file-processing system: no common schema, no central control, no constraints, no concurrency control.

Risks of continuing with files

  • Duplicate voters (redundancy): a person who moved from Rohini to Dwarka can appear in both districts’ files; nothing stops the same EPIC or Aadhaar-linked voter being entered twice.
  • Inconsistency: a correction (spelling, address, deceased status) made in one copy is not made in others; different officers hold different “truths”.
  • No validation (integrity): wrong ages (< 18), invalid constituency codes, blank mandatory fields are accepted.
  • Security: files are e-mailed and copied on pen drives; anyone with the file can read or alter every voter’s personal data; no audit trail.
  • Slow revision and lost updates: merging lakhs of rows by hand is slow; two officers editing the same file overwrite each other; a crash corrupts the file with no recovery.

Five arguments for a DBMS

  1. Deduplication by design. One central VOTER table with EPIC_No PRIMARY KEY and UNIQUE (Aadhaar_ref); the DBMS rejects a second entry. SQL can also find near-duplicates (GROUP BY name, father_name, dob HAVING COUNT(*) > 1) across all districts at once.
  2. Accuracy through integrity constraints. CHECK (age >= 18), NOT NULL on name/address, FOREIGN KEY (constituency_id) REFERENCES constituency — invalid data cannot be stored, whoever enters it.
  3. Security. Each officer logs in with an account; GRANT UPDATE only on their district’s view, read-only access for observers; encryption and audit logs show who changed which record and when.
  4. Consistency and concurrent access. All officers work on one copy; transactions and locking let thousands update simultaneously without lost updates; a correction is instantly visible everywhere.
  5. Faster revision, backup and recovery. Indexed SQL queries (e.g. all voters aged 18 by 1 January, all records flagged deceased) run in seconds instead of days of manual merging; automatic backups and log-based recovery protect against crashes; data independence lets the EC add fields (e.g. a verification_status column) without rewriting the officers’ apps.

A DBMS turns many unsynchronised spreadsheets into one controlled, constrained, secure, concurrently-updatable database — which is exactly what an accurate, duplicate-free, quickly revised electoral roll needs.

End-sem 2026 (summer) Q1(a)5 marks

A university currently maintains student records using spreadsheets. Explain how migrating to a DBMS would improve data consistency, security, data independence and concurrent access. Compare the file system and DBMS with suitable examples.

Show answer

Today the admissions office, the exam branch, the accounts section and the hostel each keep their own spreadsheet with student details — a file-processing system.

  • Data consistency. Now: a student’s phone number is in four sheets; a change in one leaves three stale copies. DBMS: one STUDENT table (Roll PK) referenced by MARKS, FEES, HOSTEL through foreign keys — the phone number is stored once, so it cannot disagree; constraints such as CHECK (marks BETWEEN 0 AND 100) keep values valid.
  • Security. Now: whoever opens the marks sheet sees and can edit everything. DBMS: user accounts and privileges — faculty may UPDATE marks only for their courses, students only SELECT their own result through a view, accounts sees fees but not grades.
  • Data independence. Now: inserting a new column (ABC-ID) shifts columns and breaks every macro/script using the sheet. DBMS: the three-schema architecture lets the university add a column or an index, or move to a new server, while existing applications and views keep working (logical and physical data independence).
  • Concurrent access. Now: “file locked for editing” or two people saving over each other at result time. DBMS: hundreds of faculty enter marks at once; transactions and locking prevent lost updates; a crash mid-update is rolled back.
BasisFile system (spreadsheets)DBMS
RedundancyName/phone in every sheetStored once, linked by Roll
QueryingManual filtering, VLOOKUP across sheetsSELECT … JOIN … in one statement

For a university with many departments sharing the same student data, the DBMS’s consistency, security, independence and concurrency outweigh its cost.

End-sem 2024 Q1(a)5 marks

A small company currently stores its data using a simple file system. The manager wants to switch to a DBMS but is unsure if it would be worth the change. Describe how this transition could benefit the company in terms of data organization, retrieval and security.

Show answer

Data organization.

  • Files: customers, orders, invoices and employees are in separate files of different formats; customer details are repeated in the orders and invoice files → redundancy and inconsistency, and data isolation.
  • DBMS: data is organised in an integrated, structured database — CUSTOMER, PRODUCT, ORDER, EMPLOYEE tables linked by keys. Each fact is stored once (controlled redundancy); constraints (PK, FK, NOT NULL, CHECK price > 0) keep it valid; the schema is documented in the data dictionary (metadata), so new staff understand the data.

Data retrieval.

  • Files: every new report needs a new program or manual work (“customers who ordered more than ₹1 lakh last quarter”).
  • DBMS: one declarative SQL query answers it; indexes and the query optimiser make it fast; many interfaces (forms for clerks, reports for the manager).

Security.

  • Files: OS-level access only — whoever opens the salary file sees all salaries; no audit.
  • DBMS: authentication, privileges (GRANT SELECT ON orders TO sales), views hiding salary columns, encryption, and audit trails.

Other gains: concurrent use by several employees without lost updates; automatic backup and crash recovery (no lost invoices); data independence for future growth.

Is it worth it? Costs are licence/hardware and training, but free DBMSs (MySQL, PostgreSQL) and cloud databases make it cheap for a small company; the reduction in errors and reporting effort justifies the switch, especially as the company grows.

Yes — better organised (integrated, non-redundant, constrained) data, faster ad-hoc retrieval with SQL, and fine-grained security.

Mid-sem 2025 Q1(a)2 marks

The administration office of a college maintains student records in multiple Excel files. Over time, files become inconsistent (same student has different addresses in different files), and data redundancy increases. Explain how moving to a DBMS can solve the problems of redundancy, inconsistency and concurrency compared to file systems.

Show answer
  • Redundancy: in a DBMS the address is stored once in STUDENT(Roll, Name, Address, …); other tables keep only Roll as a foreign key, so there is nothing to duplicate.
  • Inconsistency: with one copy an address update is automatically seen by every office; constraints (PK on Roll, FK from FEES/MARKS) stop conflicting or orphan records.
  • Concurrency: files allow one editor at a time or overwrite each other’s saves; a DBMS runs updates as transactions with locking, so several clerks can update simultaneously without lost updates, and failures are rolled back.
Mid-sem 2026 Q1(b)2 marks

A hospital database has separate files for Patients, Doctors, Appointments and Billing. The same patient information is stored in multiple files. Identify the problems illustrated by this situation and explain how a DBMS can overcome them.

Show answer

Problems: (i) data redundancy — patient name, phone, address repeated in Patients, Appointments and Billing; (ii) inconsistency — a changed phone number updated in one file only; (iii) update/delete anomalies — deleting an appointment file record may lose the patient’s details; (iv) data isolation — combining files for a bill is hard; (v) weak security of medical data.

DBMS solution: store patient details once in PATIENT(PatientID PK, …); APPOINTMENT and BILL hold only PatientID as a foreign key, so updates happen in one place and referential integrity prevents bills for non-existent patients; views and privileges let billing staff see payments but not medical history; transactions and recovery protect concurrent updates.

End-sem 2023 (ITITC05) Q1(a)4 marks

List four applications you have used that most likely employed a database system to store persistent data. Also give examples of systems in which it may make sense to use traditional file processing instead of a database approach.

Show answer

Four applications that use a database

  1. Online railway reservation (IRCTC) — trains, seats, passengers, bookings; many concurrent users booking the same seat need ACID transactions.
  2. Internet / UPI banking — accounts, balances, transactions; durability and atomicity of money transfers.
  3. E-commerce (Amazon, Flipkart) — customers, products, carts, orders, payments, reviews.
  4. University ERP / IMS portal — registration, attendance, marks, fees.

(Also acceptable: library management, social media, food delivery, Spotify playlists.)

Where file processing may make sense — when data is small, single-user, rarely shared and the DBMS overhead is not justified:

  • Embedded / real-time systems with limited memory: microwave or washing-machine controller, a car’s engine control unit, a pacemaker.
  • Single-user personal programs: a personal address book, a text editor’s settings file, a game’s save file.
  • Sequential, write-once data: server log files, sensor/scientific instrument dumps, CCTV video streams, compiler input files.
  • One-time, small applications whose development cost of a database exceeds the benefit (a one-off survey analysed in a spreadsheet).

Use a DBMS for shared, concurrent, long-lived critical data; plain files for small, single-user, embedded or sequential data.

Give the merits and demerits of a database management system.

Merits

  1. Controlled redundancy — integrated data stored once.
  2. Consistency — no conflicting copies.
  3. Data sharing among users and applications.
  4. Integrity constraints enforced centrally.
  5. Security — authentication, privileges, views.
  6. Concurrency control — many simultaneous users.
  7. Backup and recovery from failures.
  8. Data independence — physical and logical.
  9. Efficient access — SQL, indexes, optimisation.
  10. Standards, easier maintenance, faster application development.

Demerits

  1. High cost of DBMS software, hardware and storage.
  2. Complexity — needs skilled designers and a DBA.
  3. Large size — occupies much disk and memory.
  4. Performance overhead for small, simple applications.
  5. Higher impact of failure — centralised data; a failure or corruption affects all users.
  6. Cost of conversion from existing file systems and staff training.
Mid-sem 2021 Q1(a)4 marks

What is DBMS? Discuss its disadvantages.

Show answer

A DBMS is a collection of interrelated data and a set of programs to access that data; its goal is to store and retrieve information conveniently and efficiently. It lets users define (DDL), construct, manipulate (DML) and share a database while providing security, integrity, concurrency control and recovery. Examples: Oracle, MySQL, PostgreSQL, SQL Server. Database + DBMS + applications = database system.

Disadvantages

  1. Cost of hardware and software — licences, powerful processors, large memory.
  2. Size — the DBMS needs a lot of disk space and memory to run efficiently.
  3. Complexity — the DBMS, and designing a database for it, is complex; requires trained DBA and designers; a bad design hurts all applications.
  4. Performance overhead — for small single-user applications the generality (security, concurrency, logging) makes it slower than a simple file program.
  5. Higher impact of failure — all data is in one place; a hardware failure, power failure or corruption can stop the whole organisation and data may be lost if backups are not maintained.
  6. Conversion cost — moving from files to a DBMS and retraining staff.
Mid-sem 2023 Q5(b)1 mark

Explain the advantage of DBMS over file systems in terms of data redundancy and security.

Show answer

Redundancy: file systems store the same data in many files (student address in fee, exam, hostel files); a DBMS integrates data and stores each fact once, linking tables by keys — saving space and preventing inconsistency. Security: files have only OS file-level permissions; a DBMS authenticates users and grants privileges at table/column/view level (GRANT/REVOKE), so each user sees only permitted data.

Mid-sem 2024 Q1(a)2 marks

How could the lack of support for ACID properties in a file system affect the reliability of data operations compared to a DBMS, especially in financial or transactional applications?

Show answer

Take a transfer of ₹1000 from account A to B (debit A, credit B):

  • No atomicity: a crash after debiting A leaves ₹1000 lost; a file cannot roll back the half-done operation.
  • No consistency: rules like “total money unchanged” or “balance ≥ 0” are not enforced; invalid states are saved.
  • No isolation: two concurrent withdrawals both read balance 5000 and write 4000 — one withdrawal is lost (lost update); reports read half-updated data.
  • No durability: a write still in an OS buffer is lost on power failure even after the customer is told “success”.

A DBMS executes the transfer as a transaction: the log and recovery manager give atomicity and durability (undo/redo), constraints give consistency, and locking (2PL) gives isolation — so financial data stays correct even with failures and thousands of concurrent users.
