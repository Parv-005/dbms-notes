3Advantages and disadvantages of a DBMS

3.1 Advantages

Each advantage is the cure for one file-system problem — write them in that form.

AdvantageHow the DBMS achieves it
Controlled redundancyAll data is integrated in one database; each fact is stored once (normalization). Any deliberate redundancy is kept consistent by the DBMS.
ConsistencyOne copy + constraints ⇒ no conflicting versions.
Data sharingAuthorised users and many applications share the same data at the same time.
IntegrityConstraints (PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, CHECK) are declared once and checked on every insert/update.
SecurityUser accounts, passwords, views and privileges (GRANT/REVOKE); data can be encrypted; audit trails.
Concurrency controlTransactions and locking let many users update simultaneously without lost updates or dirty reads.
Backup and recoveryThe recovery subsystem uses the log to undo incomplete transactions and redo committed ones after a crash (atomicity, durability).
Data independenceThree-schema architecture: storage or logical structure can change without rewriting programs.
Efficient data accessDeclarative SQL, indexes, query optimisation, buffering.
Multiple user interfacesQuery languages for analysts, forms/menus for naive users, APIs for programmers.
Standards enforcement, reduced development time, easier maintenanceCentral control (DBA) enforces naming/format standards; new applications reuse existing data.

3.2 Disadvantages

  • Cost of software licences, faster hardware, more memory and disk.
  • Complexity — design and administration need trained staff (DBA); a bad design harms everyone.
  • Size — the DBMS itself occupies a lot of disk and memory.
  • Performance overhead for small, simple applications (security checks, logging, concurrency control).
  • Higher impact of failure — data is centralised, so a failure or corruption affects every application (single point of failure, unless replicated).
  • Conversion cost — migrating old files and retraining users.

3.3 Responsibilities of a DBMS (and what goes wrong without them)

This is Korth’s list of what the database manager (storage manager) is responsible for — asked as End-sem 2023 Q1(b).

ResponsibilityIf it is not discharged…
Interaction with the file manager — translating DML into low-level file-system commands, storing/retrieving/updating dataData could not be stored or found; every program would manage raw files itself — back to all the file-system problems.
Integrity enforcementInvalid data enters: negative balances, marks > 100, enrolments for non-existent students (dangling references).
Security enforcementAny user could read or change any data: salaries leaked, grades altered.
Backup and recoveryA disk crash or power failure loses data permanently or leaves it half-updated (₹ debited but not credited).
Concurrency controlSimultaneous users corrupt data: lost updates, dirty reads, two passengers booked on the same seat.
