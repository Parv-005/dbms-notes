8Joins and their Types

8.1 Why joins

A normalised database spreads information over several tables (employee names in employee, department names in department). A join combines rows of two (or more) tables into one result row whenever they satisfy a join condition — usually “FK = PK”.

8.2 Inner join

{{sql:j_inner}}

Older “comma” syntax gives the same result: SELECT e.name, d.dept_name FROM employee e, department d WHERE e.dept_id = d.dept_id; (forgetting the WHERE turns it into a cross join — 36 rows!). The explicit JOIN … ON form is preferred: join conditions and filter conditions stay separate.

Equi-join vs non-equi (theta) join: the condition can be any comparison, e.g. JOIN salary_grade g ON e.salary BETWEEN g.low AND g.high.

8.4 Natural join, USING, cross join

NATURAL JOIN silently joins on every common column name — risky if tables later get a column with the same name (e.g. both get created_at). USING (col) names the join column explicitly and shows it once — a safer middle ground.

8.5 Self join

{{sql:j_self}}

The same table is used twice with different aliases (e = the employee, m = the manager). LEFT JOIN keeps Aarav, who has no manager. Other self-join uses: pairs of employees in the same city (e1.city = e2.city AND e1.emp_id < e2.emp_id — the < avoids pairing someone with himself and listing each pair twice), “employees earning more than their manager”.
