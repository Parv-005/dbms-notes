6.2 Structure of a query and the order it is evaluated

SELECT   [DISTINCT] column_list / expressions / aggregates   -- 5. which columns
FROM     table_list / joins                                   -- 1. which tables
WHERE    row_condition                                        -- 2. which rows
GROUP BY grouping_columns                                     -- 3. form groups
HAVING   group_condition                                      -- 4. which groups
ORDER BY sort_columns [ASC | DESC]                            -- 6. sort
LIMIT n;                                                      -- 7. how many

Relation to RA: SELECT A FROM R, S WHERE P ≡ \pi_{A}(\sigma_{P}(R \x S)) (but SQL keeps duplicates).

More LIKE patterns: '%travel%' contains “travel”; '%@facebook.com' ends with “@facebook.com”; '____' exactly 4 characters; '50\%%' ESCAPE '\' starts with “50%”. LIKE is case-sensitive in PostgreSQL/Oracle, case-insensitive in MySQL by default.

Three-valued logic (TRUE, FALSE, UNKNOWN)

Any comparison involving NULL yields UNKNOWN. WHERE keeps a row only if the condition is TRUE (UNKNOWN rows are dropped).

6.4 SELECT list — DISTINCT, expressions, aliases

{{sql:s_distinct}}{{sql:s_expr}}
  • SELECT * — all columns. SELECT DISTINCT — remove duplicate rows (applies to the whole row, not one column).
  • Column alias: salary * 12 AS annual_salary. Table alias: FROM employee e (then e.name).
  • An alias defined in SELECT cannot be used in WHERE (WHERE runs before SELECT) but can be used in ORDER BY.
  • Useful functions: UPPER, LOWER, LENGTH, SUBSTR, CONCAT / ||, ROUND, COALESCE, CASE WHEN … THEN … ELSE … END, date functions YEAR(d), EXTRACT(YEAR FROM d), CURRENT_DATE.
SELECT name,
       CASE WHEN salary >= 70000 THEN 'High'
            WHEN salary >= 50000 THEN 'Medium'
            ELSE 'Low' END AS band
FROM   employee;

6.5 ORDER BY and LIMIT

{{sql:s_order}}
  • Default is ASC. Several keys: sort by the first, ties broken by the second, …
  • You may sort by a column not in the SELECT list, by an alias, or by position (ORDER BY 2).
  • Without ORDER BY the row order is not guaranteed (relations are unordered).
{{sql:s_limit}}

Top-N syntax differs: MySQL/PostgreSQL/SQLite LIMIT n [OFFSET k]; SQL Server SELECT TOP n …; Oracle 12c+/standard FETCH FIRST n ROWS ONLY (older Oracle: WHERE ROWNUM <= n). Note that LIMIT 3 cut the tie arbitrarily here — for “employees with the top 3 salaries” use a sub-query or DENSE_RANK (section 9.7).

6.6 Set operations — UNION, INTERSECT, EXCEPT

Combine the results of two SELECTs with the same number of columns and compatible types (union-compatible, exactly as in RA).

{{sql:s_union}}{{sql:s_intersect}}{{sql:s_except}}{{sql:s_unionall}}
  • UNION, INTERSECT, EXCEPT remove duplicates; UNION ALL (and INTERSECT ALL, EXCEPT ALL) keep them. UNION ALL is faster (no duplicate elimination).
  • Oracle writes MINUS for EXCEPT. MySQL supports INTERSECT/EXCEPT only from version 8.0.31 — otherwise use IN / NOT IN / NOT EXISTS.
  • UNION vs JOIN: UNION stacks rows of two results vertically (same columns); JOIN combines columns of two tables horizontally.
