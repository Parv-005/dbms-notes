2Integrity Constraints

2.1 What and why

Definition

Integrity constraints are rules, declared as part of the database schema, that every legal database state must satisfy. The DBMS checks them automatically whenever data is inserted, updated or deleted, and rejects any operation that would violate them. They guard the database against accidental damage by authorised users — wrong, missing, duplicate or dangling data.

Integrity vs security: integrity protects against accidental invalid changes by authorised users; security protects against unauthorised access (GRANT/REVOKE, Unit 5). Why declare them in the DBMS rather than in programs? Written once instead of in every application, cannot be bypassed, and stored in the catalog where everyone can see them (Codd’s rule 10, integrity independence).

2.2 Domain constraints — data type, NOT NULL, CHECK, DEFAULT

A domain constraint specifies the set of values an attribute may take. Every value must be atomic and belong to the attribute’s domain.

  • Data type — INT, DECIMAL(8,2), VARCHAR(30), DATE … A value of the wrong type is rejected (storing 'A' in an INT age column).
  • NOT NULL — the attribute must always have a value: name VARCHAR(40) NOT NULL.
  • CHECK (condition) — the value must satisfy a condition: CHECK (age BETWEEN 16 AND 40), CHECK (color IN ('red','green','blue','black')), CHECK (salary > 0). A CHECK may also involve several columns of the same row: CHECK (end_date >= start_date) (then it is written at table level).
  • DEFAULT value — value stored when an INSERT does not give one: building VARCHAR(20) DEFAULT 'Main'.
  • User-defined domain (standard SQL): CREATE DOMAIN marks_t AS INT CHECK (VALUE BETWEEN 0 AND 100); then use marks marks_t.
CHECK and NULL

A CHECK constraint is violated only when the condition is FALSE. If the value is NULL the condition is UNKNOWN, which is accepted. So CHECK (age >= 16) still allows a NULL age — add NOT NULL if the value is mandatory. (Older MySQL versions, before 8.0.16, parsed CHECK but silently ignored it.)

2.3 Key constraints and entity integrity — PRIMARY KEY, UNIQUE

  • Key constraint: no two tuples may have the same value for a key. Declared with PRIMARY KEY (the chosen key) and UNIQUE (alternate keys).
  • Entity integrity constraint: no attribute of the primary key may be NULL. Reason: the PK is how we identify a tuple (and how other tables refer to it); a NULL key would make the row unidentifiable, and two NULL keys could not be told apart.

A composite PK or UNIQUE must be written at table level: PRIMARY KEY (student_id, course_id, semester) — this says the combination is unique (a student may take many courses, but not the same course twice in the same semester).

2.4 Referential integrity — FOREIGN KEY

Definition

A referential integrity constraint is specified between two relations. If attribute set FK of the referencing (child) relation R1 refers to the primary key PK of the referenced (parent) relation R2, then for every tuple t1 in R1, the value t1[FK] must either be NULL or be equal to t2[PK] for some tuple t2 in R2.

In words: a foreign key may not point to something that does not exist (“no dangling references”).

Which operations can violate it?

CREATE TABLE employee (
  emp_id   INT PRIMARY KEY,
  name     VARCHAR(40) NOT NULL,
  dept_id  INT,
  CONSTRAINT fk_emp_dept FOREIGN KEY (dept_id)
      REFERENCES department(dept_id)
      ON DELETE SET NULL
      ON UPDATE CASCADE
);
Cascades can chain — self-referencing table (PYQ End-Sem 2024)

Table T(A, C): A is the PK, C is an FK referencing A with ON DELETE CASCADE. Tuples: (2,4) (3,4) (4,3) (5,2) (7,2) (9,5) (6,4). Deleting (2,4) deletes every tuple whose C = 2, i.e. (5,2) and (7,2); deleting (5,2) in turn deletes the tuple with C = 5, i.e. (9,5); nobody has C = 7 or C = 9, so the chain stops.

2.5 Enforcing integrity constraints

“Enforcing” = where the constraints are written and how/when the DBMS checks them.

  1. Declaratively, in CREATE TABLE (best). Two styles:
    • Column-level — written next to the column: age INT CHECK (age >= 16). Only for single-column constraints. (NOT NULL can only be column-level.)
    • Table-level — written after all columns: PRIMARY KEY (sid, cid), FOREIGN KEY (sid) REFERENCES student(roll_no), CHECK (end_date >= start_date). Needed for multi-column constraints.
    Give constraints names with CONSTRAINT name … so error messages are readable and they can be dropped later.
  2. Added / removed later with ALTER TABLE: 
    ALTER TABLE parts   ADD CONSTRAINT chk_color CHECK (color IN ('green','red','blue','black'));
ALTER TABLE student ADD CONSTRAINT uq_email UNIQUE (email);
ALTER TABLE student ADD CONSTRAINT fk_dept FOREIGN KEY (dept_id) REFERENCES department(dept_id);
ALTER TABLE student DROP CONSTRAINT chk_age;          -- MySQL: DROP CHECK chk_age
    When a constraint is added to a table that already has data, the DBMS first checks the existing rows; if any violates it, the ALTER fails.
  3. Checking time. By default every constraint is checked immediately — after each SQL statement. If it fails, the whole statement is rolled back and an error is returned (the transaction may continue). A constraint declared DEFERRABLE INITIALLY DEFERRED is checked only at COMMIT — needed for “chicken-and-egg” cases such as two tables with FKs to each other (Oracle, PostgreSQL).
  4. General constraints that span several tables cannot be expressed as column/table constraints:
    • Assertion (standard SQL, rarely implemented): CREATE ASSERTION max_staff CHECK (NOT EXISTS (SELECT dept_id FROM employee GROUP BY dept_id HAVING COUNT(*) > 50));
    • Triggers (section 11) — procedural code fired on INSERT/UPDATE/DELETE that can check anything and raise an error.
  5. Application code — the weakest option: can be bypassed by any other program or by direct SQL.

Complete example — every constraint type, and what the DBMS does

CREATE TABLE department (
  dept_id    INT          PRIMARY KEY,                      -- key + entity integrity
  dept_name  VARCHAR(30)  NOT NULL UNIQUE,                  -- domain + alternate key
  building   VARCHAR(20)  DEFAULT 'Main'                    -- default value
);
CREATE TABLE student (
  roll_no    INT          PRIMARY KEY,
  name       VARCHAR(40)  NOT NULL,
  email      VARCHAR(50)  UNIQUE,
  age        INT          CHECK (age BETWEEN 16 AND 40),
  dept_id    INT,
  FOREIGN KEY (dept_id) REFERENCES department(dept_id)      -- referential integrity
      ON DELETE SET NULL ON UPDATE CASCADE
);
