9Sub-queries and Correlated Sub-queries

9.1 What a sub-query is

Definition

A sub-query (nested / inner query) is a SELECT statement written inside another SQL statement (the outer query), enclosed in parentheses. It can appear in WHERE, HAVING, FROM (derived table), the SELECT list (scalar sub-query), and in INSERT / UPDATE / DELETE.

Kind (by result)ReturnsUsed with
Scalar (single-row) sub-queryone value (1 row × 1 column)= <> < > <= >=
Multi-row sub-queryone column, many rowsIN, NOT IN, ANY / SOME, ALL
Table sub-querymany rows and columnsEXISTS, NOT EXISTS, FROM clause

By dependence on the outer query: non-correlated (independent — runs once) vs correlated (refers to the outer row — re-evaluated per outer row). Section 9.5.

Edge cases: > ALL of an empty set is TRUE; > ANY of an empty set is FALSE. (MySQL, Oracle, PostgreSQL and SQL Server support ANY/ALL; SQLite does not, which is why the equivalent MIN/MAX form is useful.)

PYQ 2023-style: “Find the ID of each employee who earns more than every employee of Small Bank Corporation” → salary > ALL (SELECT salary FROM works WHERE company_name = 'Small Bank Corporation').

9.5 Correlated sub-queries

Definition

A correlated sub-query is a sub-query that refers to a column of the outer query. It cannot be evaluated on its own; logically it is executed once for every row processed by the outer query, using that row’s values.

For Meera (dept 10) → AVG dept 10 = 54333 → ✔. For Zoya (dept NULL) the inner WHERE x.dept_id = NULL is never true → AVG of nothing = NULL → comparison UNKNOWN → not returned.

Ties are handled automatically (if two employees share the department maximum both are returned). The same with a non-correlated derived table:

SELECT e.name, e.dept_id, e.salary
FROM   employee e
JOIN  (SELECT dept_id, MAX(salary) AS mx FROM employee GROUP BY dept_id) m
       ON m.dept_id = e.dept_id AND e.salary = m.mx;

Exam — “frame the question for this query” (Mid-Sem 2026)
SELECT B.BookingID, B.PassengerID, B.Fare
FROM   BOOKING B
WHERE  B.Fare > (SELECT AVG(B2.Fare) FROM BOOKING B2 WHERE B2.PassengerID = B.PassengerID);

The inner query is correlated on PassengerID, so it computes the average fare of the same passenger. Question: “Display the booking ID, passenger ID and fare of every booking whose fare is higher than the average fare of all bookings made by that same passenger.”
